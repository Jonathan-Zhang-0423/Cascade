# Remove Vibe Agent, Unify Through Manager+Editor

## What & Why
The Vibe Agent was the original "do-everything" assistant before Plan Mode / Build Mode existed. It now only serves one remaining role: handling free-form typed messages in Build mode when no plan is actively executing. This creates an architectural inconsistency — users can bypass the Manager's structured planning entirely by switching to Build mode and typing directly.

The goal is to remove the Vibe Agent and route all user interactions through the Manager → Editor pipeline:
- **Plan Mode**: Manager Agent (unchanged)
- **Build Mode, free-form typed message**: Manager creates a minimal plan → Editor executes it
- **Build Mode, executing plan steps**: Editor Agent (unchanged)

This also naturally fixes Task #31 (plan context loss on mode switch) since Build mode messages no longer skip the Manager.

## Done looks like
- Typing directly in Build mode creates a quick plan (1-step or multi-step as needed) and executes it, exactly like Plan Mode → "Start building" — but seamlessly in one step
- The "Plan Mode" toggle still works as before for multi-turn brainstorming before committing to build
- No reference to "Vibe Agent" anywhere in the active code path (server or client)
- `server/vibe-prompt.ts` is either deleted or kept as a dead file (safe to keep for reference)
- `POST /api/chat` with no `mode` defaults to Editor Agent (not Vibe Agent) as a safe fallback
- The project auto-naming marker `[[PROJECT_NAME:...]]` still works (needs to move to Manager or Editor prompt)

## Out of scope
- Changing the Plan Mode / Manager Agent behavior
- Changing the Editor Agent behavior during plan execution
- Changing the Communicator or Verifier agents
- Redesigning the chat UI

## Tasks

1. **Remove Vibe Agent from `/api/chat` fallback** — In `server/routes.ts`, change the `/api/chat` endpoint so the default (no `mode` field) uses `EDITOR_AGENT_SYSTEM_PROMPT` + `buildEditorContextMessage` instead of `VIBE_AGENT_SYSTEM_PROMPT`. This makes the Editor the universal non-Manager agent.

2. **Reroute Build mode free-form sends to Manager** — In `chat-panel.tsx`, remove `handleSend()` as the Build mode handler. Instead, when `chatMode === "build"` and the user types a free-form message (no active plan execution), route through `handleManagerSend()`. The Manager will produce a plan, and the "Start building" button / auto-trigger will execute it. This collapses the two-mode routing into one consistent pipeline and also fixes the plan context loss bug (#31).

3. **Move project auto-naming to Manager** — The `[[PROJECT_NAME:...]]` marker is currently generated by the Vibe Agent on first response. Move this to the Manager Agent system prompt so it fires on the first Manager response to a new project. Ensure the extraction logic in `chat-panel.tsx` still works across both manager messages and chat messages.

4. **Clean up dead Vibe code paths** — Remove or mark `handleSend` as deprecated in `chat-panel.tsx`. Ensure `handleCurrentSend` no longer references the Vibe path. The server file `vibe-prompt.ts` can stay but should no longer be imported by active routes.
