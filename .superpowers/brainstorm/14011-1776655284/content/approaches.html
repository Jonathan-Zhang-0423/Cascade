Three approaches to dual-layout

How should the desktop and mobile layouts coexist?

A

CSS breakpoint split (Recommended)

One codebase, one router. useIsMobile() hook gates which layout renders. Desktop keeps the resizable panel IDE. Mobile renders a completely separate component tree: full-screen chat, swipe-to-preview, floating pill. PWA manifest + service worker added at the app level.

Pros

  • Single deployment, single URL
  • No state sync needed — same Zustand store
  • Clean separation: mobile components are new files

Cons

  • Two component trees to maintain long-term
B

Responsive panels (adapt existing layout)

Add Tailwind responsive classes to the existing ide.tsx and panels. On narrow screens, hide the editor, stack panels vertically, collapse the dock into a bottom bar. No new component files — everything adapts in place.

Pros

  • Fewest new files
  • No branching logic

Cons

  • ResizablePanels don't support touch well
  • Mobile UX will feel like a shrunk desktop app
  • Hard to achieve the "native phone feel" goal
C

Separate mobile route

Add a /m/project/:id route that serves a fully independent mobile app shell. Desktop keeps /project/:id unchanged. Server detects user-agent and redirects mobile browsers automatically.

Pros

  • Zero risk to desktop layout
  • Mobile can be iterated independently

Cons

  • Two routes = two state sync problems
  • PWA manifest tied to one URL — split URLs complicate install
  • User-agent detection is fragile
