Design Section 5 of 5: Micro-animations & Final Polish

The last layer — motion and timing that makes the whole thing feel alive. Does this direction feel right?

5A — Transition Tokens

New CSS variables added to index.css. All existing components opt in by replacing hardcoded transition-* classes.

--transition-fast: 100ms ease;/* hover states, icon swaps */
--transition-base: 150ms ease;/* button presses, tab switches */
--transition-slow: 250ms ease;/* panel reveals, card expansions */
--transition-spring: 200ms cubic-bezier(0.34,1.56,0.64,1);/* step completion pop */

These replace ad-hoc duration-200 / transition-all scattered across components. One source of truth for all timing.

5B — Step Completion Animation

When a plan step transitions from running → done, it currently just swaps the icon. Proposed: a brief pop + color shift.

State sequence
Add auth state management
Running...
1. running
Add auth state management
Done
2. pop (spring, 200ms)
Add auth state management
3. settled (fade, 250ms)
Implementation:
@keyframes step-complete
0% { transform: scale(1); }
40% { transform: scale(1.25); box-shadow: 0 0 0 6px #16a34a20; }
100% { transform: scale(1); box-shadow: none; }

Duration: 200ms spring. Triggers once when status changes to "done". No loop.

5C — File Write Flash

When a file is written in the action log, the row briefly highlights blue then fades. Draws the eye to what changed without being distracting.

  100% { background: #0d1f12; border-left-color: #22c55e; }
}
/* duration: 600ms ease-out, runs once on mount */

5D — Build Phase Fade-In

Each new plan step and action log entry fades up from 4px below. Keeps the stream feeling live without jarring jumps.

@keyframes fade-up {
  from { opacity: 0; transform: translateY(4px); }
  to   { opacity: 1; transform: none; }
}

/* Applied to: new ActionLogLiveRow, new StepItem, BuildCompletionCard */
/* Duration: 150ms ease — fast enough not to feel slow */

Only runs on newly added rows, not on re-renders. Triggered by mount, not by data changes.

5E — Hover & Focus States

Audit of interactive elements that currently have no hover feedback. Uniform treatment applied:

Dock buttons
Idle (25% opacity) → Hover (70% opacity, 100ms)
Toolbar icon buttons
Idle → Hover: bg lightens, border brightens (100ms)

Only touches index.css and isolated component class additions. No logic changes. Does this final section look right?
