# Streaming Action Log + Completion Summary

## What & Why
During both Plan and Build mode agent runs, each discrete action (thinking, tool call, file edit, current step) should stream visibly in the chat panel as it happens. Once the agent finishes, those live action entries should automatically collapse into individually-expandable "chips" — matching the UI shown in the reference screenshots (screenshot 1 = collapsed state, screenshot 3 = expanded file-content view). In Build mode, after all action chips are collapsed, the agent should output a structured completion message (screenshot 2): a confirmatory headline, a numbered file-by-file change summary, and any special notes.

## Done looks like
- While the agent is running (Plan or Build), the chat panel streams each action as it happens:
  - **Current step** — which task/step is actively being worked on
  - **Thinking** — the AI's live reasoning tokens, labeled "思考过程" / "Thinking"
  - **Tool calls** — each command executed (e.g. "执行命令 curl …", "测试代码"), labeled with type + truncated detail
  - **File edits** — each file read or written (e.g. "阅读文件 index.html", "创建文件 game.js"), labeled with filename
- When the agent finishes, all streamed action entries automatically collapse into compact expandable chips in-place (no re-render jank). Each chip shows an icon + short label.
- Clicking a chip expands it to reveal the full content that was streamed (e.g. full file contents, full thinking text, full command output) — matching screenshot 3 layout with a file viewer style for file edits.
- In **Build mode only**, after the collapsed chips, the agent outputs a completion message containing:
  1. A bold confirmatory headline (e.g. "✅ Build complete!" / "✅ 构建完成！")
  2. A numbered list of every changed file, each entry stating: the file path, what was changed, why it matters to the project, and what the change does functionally
  3. A "Special notes" section if the agent has anything important to flag (caveats, known issues, next steps)
- The completion message is generated by a prompt that instructs the Communicator/Narration agent to produce this structured output after the build loop finishes.

## Out of scope
- Changing the underlying streaming SSE protocol or agent models
- Retroactively adding action chips to messages that arrived before this feature is deployed
- Plan mode completion summary (Plan mode already produces a plan card; only Build mode gets the new summary)

## Tasks
1. **Action event model** — Define a typed action-log event shape (type: `thinking | tool_call | file_read | file_write | step`, label, detail, timestamp) that the frontend accumulates per-agent-turn as SSE events arrive. Map existing stream events (`thinking_token`, `code_applied`, `step_starting`, tool/command events) to this shape.

2. **Live streaming action list UI** — While the agent is running, render each action-log entry as an expanding live row in the chat panel (icon + label + streaming content). Use the existing `thinking_token`, `step_starting`, `code_applied`, and narration events as data sources. Ensure file-edit rows show the filename and stream the content in a code-viewer style (matching screenshot 3).

3. **Auto-collapse on completion** — When the agent turn ends (build complete or plan complete), replace the live action list with collapsed chip variants in-place. Each chip: small icon, short label (truncated at ~40 chars), expand/collapse toggle. Clicking a chip reveals the full buffered content. Default state is collapsed.

4. **Build completion summary prompt + display** — After the build loop finishes, trigger a prompt to the Communicator agent instructing it to output the structured completion message: (1) confirmatory headline, (2) numbered file-change list with file path + what changed + significance + functional impact, (3) special notes section if applicable. Render this as a styled completion card beneath the collapsed chips.
